# Bullet Rewriting Formula

The core blueprint for crafting resume bullet points that communicate engineering impact clearly and concisely.

---

## The 4-Part Formula

Every bullet point must be structured using these four mandatory components:

$$\text{[1. Strong Action Verb]} + \text{[2. Core Task / Problem Solved]} + \text{[3. Tools & Tech Stack]} + \text{[4. Quantifiable Impact / Metric]}$$

### Breakdown of Components

| Component | Purpose | Good Example | Bad Example |
|---|---|---|---|
| **1. Action Verb** | Sets an active, decisive tone | *Engineered*, *Optimized*, *Architected* | *Worked on*, *Was involved in* |
| **2. Task / Core Feature** | Explains what system or feature was handled | *REST API authentication service* | *a backend feature* |
| **3. Tech Stack / Tools** | Demonstrates concrete technical mastery | *using Python, Docker, and PostgreSQL* | *using programming tools* |
| **4. Quantifiable Impact** | Proves real-world value with metrics | *reducing response latency by 40%* | *making it faster* |

---

## Formula Rules & Formatting Guidelines

### 1. Lead with High-Impact Action Verbs
- Never begin a bullet with passive phrasing (*"Responsible for..."*, *"Assisted in..."*, *"Helped team to..."*).
- Match the verb category to the domain (e.g., *Architected* for cloud systems, *Trained* for ML models).

### 2. Explicitly Name Technologies
- Include specific frameworks, languages, cloud services, and tools (*PyTorch*, *React*, *Kubernetes*, *PostgreSQL*).
- Group related tools logically rather than dumping a raw list.

### 3. Always Include a Metric or Outcome
If an exact metric is not provided in raw notes, apply reasonable estimations using realistic bounds:
- **Efficiency/Speed:** *"reducing latency by 30%"*, *"cutting load times by ~40%"*
- **Volume/Scale:** *"processing 10K+ daily events"*, *"serving 500+ active users"*
- **Quality/Accuracy:** *"achieving 94% model precision"*, *"reducing build errors by 50%"*
- **Time Saved:** *"saving 5+ engineering hours per week"*

> [!TIP]
> Use approximation symbols like `~`, `+`, or `up to` when metrics are estimated (e.g., `processing ~15K requests/sec`).

### 4. Bolding Strategy for Scannability
Highlight key technologies, metrics, and outcomes to catch the recruiter's eye within 6 seconds:
- Bold key technologies: `\textbf{Python}`, `\textbf{Docker}`
- Bold metrics: `\textbf{35\% reduction}`, `\textbf{10K+ requests}`

## Complete Formula Examples (Anonymized)

### Example 1: Software Engineering
* **Raw:** *"Made a web scraper to get product prices from websites using Python."*
* **Formulated Output:** *"Engineered an automated web scraper in \textbf{Python} using \textbf{BeautifulSoup} and \textbf{Selenium}, extracting data across 50+ target sites and cutting manual data collection time by \textbf{80\%}."*

### Example 2: Data Science & AI
* **Raw:** *"Trained an image classifier model with PyTorch."*
* **Formulated Output:** *"Developed a Convolutional Neural Network (CNN) in \textbf{PyTorch}, achieving \textbf{93.5\% accuracy} on a dataset of 20K+ images and optimizing inference speed by \textbf{25\%} via model quantization."*

### Example 3: Cloud & DevOps
* **Raw:** *"Set up CI/CD pipeline on GitHub Actions for docker containers."*
* **Formulated Output:** *"Architected an automated CI/CD pipeline utilizing \textbf{GitHub Actions} and \textbf{Docker}, streamlining container deployment to AWS and reducing deployment cycles from 45 to \textbf{10 minutes}."*
